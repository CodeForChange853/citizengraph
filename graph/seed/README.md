# Curated seed data

Hand-curated YAML derived from `data/raw/*.xlsx`; this folder is the source of truth for the
official charter graph. Rules and known data issues: `docs/charter_data.md`. What is in and out:
`docs/seed_status.md`. Per-service review checklist: `docs/seed_review.md`.

| File | Records |
|---|---|
| `offices.yaml` | offices |
| `services.yaml` | one per curated service (`charter_ref` = the draft id, e.g. `BPLO-01`) |
| `requirements.yaml` | checklist lines; groups (`group: true`) and their children (`parent_id`) |
| `steps.yaml` | steps with parsed durations, `role`, `external_agency`, explicit `next_id` chain |
| `fees.yaml` | fee rows (`step_id`, optional variant links) |
| `variants.yaml` | condition values (`dimension:value`) linked from requirements and fees |

Conventions:

- Every record has `review_status` (`needs_review` until a human checks it against the sheet) and a
  `source` (file, sheet, row range of the service block; rows carry `source_row`). Blank or unclear
  charter data is `null` plus a `flags` entry, never a guess.
- `condition_text` keeps the charter's wording; `variant_ids` are structured links;
  `condition_structured: false` means the links do not capture the whole condition.
- Staff names exist only in `internal_person_raw` on steps. They are never loaded into Neo4j,
  never dumped by the models, never shown. `role` is set only when the charter gives a role title.
- Agency and Role nodes are derived from `secured_at` and `role` strings (the ids are slugs).
- Validate with `python -c "from citizengraph.graph import load_seed; load_seed()"`; regenerate
  `docs/seed_review.md` with `python -m citizengraph.graph.review` after editing.
- The `draft/` folder is generated by `python -m citizengraph.parsing` and is not loaded.
